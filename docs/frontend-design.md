# Frontend Design — Quiet Precision

> Status: **Phase 6.4** — IDEMPOTENT PRESENT ATTENDANCE MARKS + LIVE PRESENT STATE. PHASE 6.4 introduces the live persisted PRESENT state on `/classes/[classId]/attendance`. The Server Component now reads `getAttendancePresentStateForCurrentTeacher(classId)` and renders an `AttendancePresentStatePanel` Server Component with `Recorded present {presentCount} / {rosterCount}` and a list of `{fullName, identificationCode, recognizedAt}` sorted `recognizedAt` ASC. The `AttendanceCameraClient` calls `router.refresh()` after a successful scan whose `recordedCount > 0` so the Server Component re-fetches the persisted state. The persisted state is the SINGLE SOURCE OF TRUTH for the present list — the camera client's local preview is allowed to remain visible but is explicitly NOT authoritative. PHASE 6.4 does NOT add `absent` / `late` labels, does NOT add a manual mark UI, does NOT add continuous scanning controls, and does NOT introduce a second permanent attendance state in client memory.

This document is the **visual constitution** for the Face Attendance application. All UI work — present and future — must read and follow this document before implementation.

---

## Design Philosophy

The product design language is **Quiet Precision**.

It must feel: **professional, calm, refined, human, friendly, trustworthy, precise, modern, high-quality.**

The interface should feel carefully designed by a professional product design team, not automatically generated by AI.

Inspiration may come from the restraint and consistency of Linear, Vercel, Notion, and modern high-quality SaaS products. **Do NOT clone any brand.** Borrow principles, not exact visual identity.

---

## Anti-AI-Design Rules

**STRICTLY AVOID:**

- Purple AI gradients
- Blue-purple gradient backgrounds
- Neon, glow effects
- Glassmorphism everywhere
- Oversized rounded cards (rounded-3xl everywhere)
- Giant hero typography inside application pages
- Excessive shadows
- Random color accents
- Decorative blobs, floating elements
- Excessive animation, bounce/spring interactions
- Fake analytics, fake data
- Card-inside-card-inside-card layouts
- Random Tailwind values
- Inconsistent spacing
- Different design languages between pages

The application should look **restrained and intentional**.

## Theme Strategy

### Light-First Principle

**Light is the primary/default experience.**

First-time users must always see Light regardless of OS preference. Users can explicitly switch to Dark.

Theme persistence: saved to `localStorage` key `face-attendance-theme` via next-themes.

```ts
<ThemeProvider
  attribute="class"
  defaultTheme="light"
  enableSystem={false}   // Do not follow OS preference
  disableTransitionOnChange
  storageKey="face-attendance-theme"
  themes={["light", "dark"]}
/>
```

### Hydration Safety

An inline `<script>` runs synchronously before React hydration to attach the correct `light`/`dark` class to `<html>`. This prevents theme flashing on first paint.

## Radius System

**Restrained.** Never rounded-3xl in the app shell.

| Token | Value | Usage |
|---|---|---|
| `sm` | 6px | Small badges, tooltips |
| `md` | 8px | Controls, inputs |
| `lg` | 10px | Menus, dropdowns |
| `xl` | 12px | Cards, panels |
| `2xl` | 14px | Large dialogs |
| `pill` | 9999px | Specialized only |

**Rule:** Nested elements must have smaller/equal concentric radius than their parent.

---

## Shadow System

Most application cards use **border only, minimal or no shadow**. Floating UI (dropdown, popover, dialog) may use subtle layered shadows.

| Token | Usage |
|---|---|
| `--shadow-xs` | Barely visible |
| `--shadow-sm` | Card default |
| `--shadow-md` | Elevated card |
| `--shadow-lg` | Floating dropdown |
| `--shadow-xl` | Modal dialog |

---

## Motion

**Restrained.** Never bounce/spring animations.

Typical duration: **120–180ms**.

Prefer transitions on:
- `opacity`
- `background-color`
- `border-color`
- Small `transform` (e.g. scale 0.96 → 1)

Standard easing: `cubic-bezier(0.2, 0, 0, 1)` — `var(--easing-standard)`.

**Always** respect `prefers-reduced-motion`.

Do not add Framer Motion unless there is a genuinely justified requirement.

---

## Icons

**Lucide** is the single icon family used throughout. Do not mix with other icon libraries.

Coherent sizing:
- 16px: normal controls
- 18px: navigation
- 20px: larger actions

Do not use emoji as interface icons.

## Components

### Button

Four variants only:
- `primary` — main action (filled primary blue)
- `secondary` — supporting action (bordered, subtle fill)
- `ghost` — low-emphasis (transparent, hover reveals bg)
- `destructive` — confirm-and-delete flows (red)

Two sizes: `md` (36–40px height), `lg` (44px height). No XL buttons in Phase 2.

### Input

- Height: 40px
- Radius: 8px
- Border: 1px subtle (`--color-input`)
- Focus: primary border + 2px primary ring
- Error: destructive border

Labels must always be visible. Never use placeholders as labels.

### Card

Default: border + no shadow. Elevated variant adds `--shadow-sm`.

### Badge

Small token for status and role display. Five tones: neutral, info, success, warning, destructive.

### Avatar

Circular surface for user identity. Google avatar image or initials fallback. Four sizes: sm (32px), md (40px), lg (48px), xl (64px).

### Empty State

Never display only "No data". Always include:
1. Short title
2. One-sentence description
3. Optional contextual action

### Skeleton

Layout-aware placeholder. Geometry should approximate final content to reduce layout shift. Subtle shimmer animation.

### Error State

Calm, useful. Avoid giant alarming screens. Clear title + short explanation + retry/back action where appropriate. Never expose raw error messages to end users.

## Pages

### /login

Desktop: two-column split.
- **Left:** Restrained brand panel. Geometric brand mark. Short product statement. Feature pills. No stock imagery, no AI gradient, no glowing face illustration.
- **Right:** "Welcome back" headline, Google sign-in button, privacy note.

Mobile: single-column, left panel hidden.

### /onboarding

Two-step flow with a Stepper indicator ("Step 1 of 2", "Step 2 of 2").
- Step 1: Role selection cards (Student / Teacher). Selected state: primary border + subtle primary background.
- Step 2: Personal information form. Google identity displayed read-only.

### /dashboard

Real data only. No fabricated metrics.
- Welcome section with real name
- Profile summary card
- Role-aware empty state for workspace
- Face ID "Not configured" status

No fake attendance percentages, charts, or student counts.

### /profile

Sections:
1. **General information** — full name, identification code, phone, edit form
2. **Account** — role (read-only), sign-in method
3. **Face ID** — "Not configured" status

Avoid one giant floating card.

### Root /

Public landing page. Brand headline, feature strip, phase plan. Links to /login.

## Accessibility

- Keyboard navigation throughout
- Visible focus states (`:focus-visible` ring in primary color)
- Semantic HTML (`<nav>`, `<main>`, `<header>`, `<aside>`, `<button>`, etc.)
- `aria-label` on icon-only buttons
- `aria-invalid` on inputs with errors
- `aria-describedby` linking inputs to their help/error text
- `role="alert"` on error messages
- `role="status"` on success messages
- `aria-current="step"` on active stepper step
- `aria-disabled` on disabled-but-visible nav items
- Minimum 4.5:1 contrast for body text
- Minimum 3:1 contrast for large text and UI components
